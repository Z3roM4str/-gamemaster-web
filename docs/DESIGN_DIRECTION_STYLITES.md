# GameMaster — Design Direction: STYLITES × Game Pass × Netflix

## Status

This document defines the current art-direction target for the next major visual iteration of GameMaster.

It is subordinate only to `docs/CODEX_VISUAL_GUARDRAILS.md` for the distinction between chromostereopsis and anaglyph/RGB-split effects. If an older visual instruction conflicts with this document, use this document.

## Reference

Primary composition reference:

- https://www.mek.gallery/releases/stylites

Use STYLITES as a reference for **how the whole viewport/page behaves as one graphic composition**, not as a template to clone. Do not reproduce its artwork, exact layout, typography, transitions or page structure.

GameMaster must remain a commercial entertainment catalog with its own information architecture, content and brand language.

## Core synthesis

The target is:

- **Game Pass** for catalog architecture, browsing density, categories, rails and game-first discovery;
- **Netflix** for immediate visual recognition, cinematic content hierarchy and frictionless browsing;
- **STYLITES** for full-page composition, strong planar color fields, large-scale graphic interruptions and chromostereoscopic intensity;
- **GameMaster research** for the actual red/blue/black perceptual grammar and anti-anaglyph constraints.

The result must not look like a reskinned Netflix/Game Pass clone and must not look like an art portfolio with commerce added afterward. It should behave like a real catalog while feeling like a continuous digital artwork.

## Primary correction to the current direction

Do **not** build a conventional catalog UI first and decorate it afterward with red/blue effects.

Instead, build the page as a **single vertical composition** and place the commercial interface inside that composition.

The visual system should therefore operate at page scale:

- large chromatic masses may span multiple sections;
- section boundaries do not need to be boxed into identical cards;
- rails may cross from black into blue or interact with independent red structures;
- oversized editorial typography may participate in the composition;
- black negative space should separate high-intensity chromatic regions;
- chromatic structures should sometimes break the normal content grid while navigation and controls remain stable.

## Color-area hierarchy

The site should no longer read as a mostly-blue interface.

Use this as a **composition target, not a hard pixel quota**:

- **55–65% black / near-black** — primary environment, neutral plane, negative space, reading surface;
- **20–30% electric/spectral blue** — rear structural field;
- **10–15% electric red** — front/focal field;
- **<5% off-white / neutral gray** — text, metadata and utility surfaces.

The exact ratio can change per viewport and section, but black must be the dominant visual field across the overall experience.

### Why

- black gives the red/blue system room to work;
- too much blue creates visual saturation and fatigue;
- sparse red can have more perceptual authority than a large red field;
- neutral areas preserve trust, legibility and browsing endurance.

## Plane roles

### Black / near-black — neutral middle plane

Use for:

- page background and apertures;
- breathing room;
- reading surfaces;
- separation between strong red and blue regions;
- modal/product-detail surfaces where clarity matters.

### Blue — rear structural plane

Use for:

- technical fields;
- topology / contour systems;
- circuit/network structures;
- modular grids;
- deep section fields;
- oversized background typography or diagrams when legible;
- structural strips behind content.

Blue should not saturate every section and should not become the default card background.

### Red — front/focal plane

Use selectively for:

- selected/active states;
- primary CTA moments;
- editorial focal masses;
- high-priority section interventions;
- product focus markers;
- novelty/new-release emphasis;
- foreground geometry that clearly differs from the blue rear structure.

Red should feel scarce and intentional.

## Non-negotiable chromostereopsis rule

Never create depth by duplicating the same geometry in red/blue/cyan.

No:

- offset copies of game covers;
- red/blue text shadows;
- duplicated card shells;
- chromatic ghost borders;
- RGB split;
- chromatic-aberration filters;
- cyan ghosting;
- red/blue blur halos;
- pseudo-elements cloning the same contour.

Depth must come from **different real geometries occupying different chromatic roles**.

Examples:

- a blue circuit field behind an independent red editorial slab;
- a black aperture between a red frame and a blue internal system;
- red status geometry intersecting a neutral card while a separate blue structure exists behind the rail;
- blue topographic lines crossing a section while a red foreground mass anchors one edge.

## Original game artwork is a neutral/recognition layer

Do not repaint, tint, posterize or red/blue-split normal game cover art by default.

Original/authorized game covers should remain visually recognizable and largely color-accurate. The chromostereoscopic identity belongs primarily to the **architecture around the content**.

Use the cover as a normal content object positioned between or adjacent to chromatic planes.

This creates three useful visual systems simultaneously:

1. recognizable commercial artwork;
2. GameMaster red/blue/black spatial architecture;
3. black breathing space that prevents the catalog from becoming exhausting.

Only stylize artwork when it is a deliberate editorial asset or owner-approved procedural placeholder, never as a blanket treatment for all covers.

## Homepage composition

### Hero

The hero should be the strongest STYLITES-inspired area in terms of page-scale composition.

Requirements:

- black remains visibly present;
- one substantial blue rear structure;
- one independent red focal structure;
- normal/recognizable featured artwork when available;
- large editorial GameMaster typography without chromatic ghosting;
- concise commercial proposition;
- clear browse/catalog CTA;
- clear WhatsApp CTA;
- visual composition should extend beyond a conventional centered hero card.

Avoid making the hero a giant blue rectangle.

### Transition into catalog

The page should not abruptly switch from "art hero" to generic ecommerce rows.

Carry the same compositional field through the catalog:

- a rail may begin on black and terminate near/inside a blue field;
- an oversized red label may overlap the section edge without obscuring content;
- blue structures may continue behind multiple sections;
- black should repeatedly reopen between high-intensity regions.

## Catalog behavior — Game Pass / Netflix layer

The site still needs fast, familiar browsing.

Keep:

- horizontal rails;
- large cover art;
- search;
- filters;
- franchise/genre collections;
- clear selection states;
- product detail view/modal/route;
- related titles;
- persistent but non-aggressive quote/contact path.

Recommended gaming collections include:

- Nintendo Switch 2
- Destacados
- Mundo Mario
- The Legend of Zelda
- Pokémon
- RPG y aventuras
- Shooters
- Indie esenciales
- Otros destacados

Do not make every rail visually identical. Preserve consistent interaction mechanics, but vary the **surrounding composition**.

## Cards

Game cards should remain simple enough that the covers dominate.

Preferred:

- one real card shell or no visible shell at all;
- large unmodified cover image;
- concise title/metadata;
- black/neutral text surface where needed;
- one independent red selected/focus marker;
- blue structure may exist behind the rail or within a non-duplicated card region.

Avoid:

- generic rounded SaaS tiles;
- blue-filled card after blue-filled card;
- red/blue double borders;
- persistent neon glow;
- excessive metadata on the browsing surface.

## Universe-specific procedural language

Use distinct structural grammars while keeping the same red/blue/black system.

### Gaming

- circuit traces;
- modular game-grid geometry;
- technical glyph systems;
- controlled halftone;
- tessellations.

### Streaming

- cinematic apertures;
- signal bands;
- frame sequences;
- waveform structures;
- modular broadcast geometry.

### IA

- node networks;
- vector fields;
- scientific diagrams;
- topology lines;
- abstract data/flow systems.

These are supporting structures, not wallpaper that fills every available area.

## Typography

Typography should behave editorially at large scale while remaining commercially readable.

Use:

- oversized section labels where composition benefits;
- neutral/off-white body text;
- isolated red words or real red typographic modules;
- independent blue informational/background typography where contrast permits.

Never duplicate typography in chromatic offsets.

Avoid making every heading centered and boxed. Favor asymmetric placement where it supports the page composition.

## Motion and scrolling

Motion should reinforce independent planes, not create fake stereo.

Allowed:

- subtle parallax between genuinely different structures;
- slow reveal/crop of large background fields;
- rail movement independent from background composition;
- masked transitions between black and chromatic regions;
- mild whole-object scale/translation on focus/hover.

Forbidden:

- oscillating red/blue copies;
- RGB jitter;
- channel separation;
- constant high-frequency animation;
- motion that makes reading difficult.

The page must remain usable with reduced motion.

## Desktop composition

At ~1440px and above:

- use the viewport width aggressively;
- hero art should feel environmental rather than card-sized;
- allow art to break the content grid;
- expose multiple covers per rail;
- alternate dense catalog areas with large black breathing zones;
- do not constrain the entire page to a narrow centered column.

## Mobile composition

Mobile is a separate composition, not a scaled desktop.

Target: **vertical cinematic composition**.

Use:

- black dominant background;
- fewer but larger red/blue structures;
- chromatic fields entering from viewport edges;
- one prominent cover/artwork at a time in major editorial areas;
- thumb-scrollable rails with next-card peeking;
- compact filters/drawers;
- sticky/easily reachable contact action;
- larger safe text zones;
- fewer simultaneous high-contrast patterns than desktop.

Do not crop half the page, create horizontal page overflow or squeeze desktop navigation into phone width.

## Comfort / anti-fatigue rule

Chromostereopsis is an accent system for the entire experience, but **maximum intensity should be localized**.

High-intensity zones:

- hero;
- major transitions;
- selected product/editorial feature;
- occasional category artwork.

Low-intensity zones:

- long browsing rails;
- body copy;
- FAQ;
- purchase explanation;
- modal/detail text.

A user should be able to browse for several minutes without the entire viewport constantly vibrating with high-saturation color.

## Acceptance criteria for the next visual rebuild

The iteration is successful only if all are true:

1. The page reads primarily as black, not blue.
2. Red is visibly more strategic and materially stronger than before without becoming dominant by area.
3. The chromostereoscopic effect comes from real independent red/blue structures, never duplicated offsets.
4. The homepage feels like one continuous composition rather than a stack of unrelated UI cards.
5. The catalog still feels immediately familiar to users of streaming/game libraries.
6. Original game covers remain recognizable and are not globally tinted into the brand palette.
7. Rails retain consistent interaction but their surrounding art direction is not repetitive.
8. Desktop uses the full canvas.
9. Mobile has an intentional vertical composition and no horizontal page overflow.
10. Reading/utility surfaces remain calm enough for comfort and trust.
11. The result does not look like an anaglyph demo, RGB glitch page, generic cyberpunk template, generic SaaS dashboard or literal Netflix/Game Pass clone.
12. If all red/blue decoration is mentally removed, the information architecture and conversion path still work.

## Implementation order

For the next major iteration, prioritize:

1. page-scale composition and global black/red/blue area hierarchy;
2. hero reconstruction;
3. integration of catalog rails into the continuous composition;
4. card simplification around original cover art;
5. universe-specific structural motifs;
6. mobile re-composition;
7. motion and refinement only after static composition is strong;
8. final anti-anaglyph, accessibility, performance and responsive audits.

Do not polish the old blue-heavy composition incrementally if the structural result remains the same. Rebuild the visual composition where necessary while preserving working catalog/business functionality.
